# 길 위의 캡슐

> 같은 길을, 같은 방향으로, 같은 시간과 날씨에 달리는 사람에게만 열리는 음성 캡슐로, 혼자 운전하는 시간을 누군가와 이어진 시간으로 바꾸는 차량 전용 음성 메시지 서비스입니다.

2026 현대자동차·기아 차량용 앱 개발 공모전 출품작 · Pleos Connect

---

## 1. 길 위의 캡슐은 이런 서비스입니다

운전은 일상에서 가장 오래 혼자 있는 시간 중 하나입니다. 매일 같은 길을 수많은 사람이 지나지만, 서로의 존재를 느낄 방법은 없습니다. "이 고개는 비 오는 밤에 유난히 어둡다", "이 구간 노을은 꼭 봐야 한다"처럼 그 길을 달려 본 사람만 아는 이야기도 지도나 내비게이션에는 남지 않습니다.

길 위의 캡슐은 운전자가 길 위에서 목소리로 남긴 말을, **같은 조건으로 그 길을 지나는 다음 사람에게** 전합니다. 비 오는 밤에 남긴 말은 비 오는 밤에 같은 방향으로 그 길을 지나는 사람만 들을 수 있습니다. 얼굴도 이름도 모르는 사이지만, 같은 길을 같은 날씨에 달렸다는 사실만으로 전해지는 익명의 안부입니다.

스마트폰은 사용자가 '어디에 있는지'만 압니다. 차량은 '어느 방향으로, 어떤 날씨 속을, 어떤 상태로 달리고 있는지'를 압니다. 길 위의 캡슐은 이 차이를 서비스의 본질로 삼았습니다.
 
---

## 2. 주요 기능

- **음성 캡슐 남기기.** [캡슐 남기기] 버튼을 한 번 누르면 이후는 모두 음성으로 진행됩니다. 차가 "남길 말을 해주세요"라고 묻고, 운전자가 말하면(최대 30초) 내용을 다시 들려준 뒤 "등록·다시·취소" 중 하나를 음성으로 고릅니다. 버튼을 누른 순간의 위치, 진행 방향, 시간대, 차량 상태가 캡슐에 함께 담깁니다.

- **네 가지 조건이 맞을 때만 열리는 캡슐.** 캡슐은 ① 반경 150m 안에서 ② 같은 진행 방향(±45°)으로 ③ 같은 시간대에 ④ 같은 차량 상태일 때만 열립니다. 하나라도 다르면 같은 자리를 지나도 열리지 않습니다.

- **발견과 재생.** 조건이 맞으면 "누군가 남긴 캡슐이 있어요"라는 안내와 함께 메시지가 음성으로 재생되고, 화면에는 자막이 표시됩니다.

- **나의 도감.** 열어 본 캡슐은 "비 오는 밤의 해안도로"처럼 조건이 담긴 이름으로 사용자별로 수집됩니다. 달려 온 길이 기록으로 쌓입니다.

### 캡슐이 열리는 조건

| 조건 | 판단 기준 | 데이터 |
|---|---|---|
| 위치 | 캡슐 지점에서 반경 150m 안 | FusedLocation SDK |
| 방향 | 캡슐을 남긴 진행 방향 ±45° | FusedLocation SDK |
| 시간대 | 낮(06~19시) · 밤(19~04시) · 새벽(04~06시) | 시스템 시각 |
| 차량 상태 | 와이퍼 OFF = 맑음, AUTO·LOW = 비, HIGH = 폭우 | **Vehicle SDK** |

날씨는 기상 정보가 아니라 **그 차가 실제로 겪고 있는 비**, 즉 와이퍼 상태로 판단합니다. 차량 데이터가 없으면 캡슐은 열리지 않습니다.

### 주행 중 안전

- 주행 중 화면 조작은 [캡슐 남기기] 버튼 한 번뿐입니다. 확인과 등록은 모두 음성으로 합니다.
- 캡슐은 한 번에 하나만 재생하고, 캡슐을 남기는 동안에는 새 캡슐 안내를 멈춥니다.
- 이미 들은 캡슐과 자신이 남긴 캡슐은 다시 열리지 않습니다.
- 도감과 시연 패널은 정차(P단) 중에만 열립니다.

### 개인정보 보호

음성은 차량 안(ON_DEVICE)에서 문장으로 변환하며, 녹음 원본은 저장하지 않고 변환된 문장만 캡슐에 담습니다. 캡슐을 들은 사람에게는 작성자 정보를 보여 주지 않습니다. 기기 백업과 기기 간 데이터 이전을 막았고, 제출 APK는 상세 로그를 끈 상태로 빌드해 이동 경로와 대화 내용이 기록에 남지 않습니다.

## 5. 실행 방법

### 설치

Pleos Connect Emulator v2.1.0을 Cold Boot로 실행한 뒤 APK를 설치합니다.

```bash
adb install -r apk/gilcap_길위의캡슐_release.apk
```

소스에서 빌드할 경우:

```bash
./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```


### 2. 필요한 설정

| 설정 | 방법 | 용도 |
|---|---|---|
| Virtual Console | `adb forward tcp:8088 tcp:8088` → 브라우저 `http://127.0.0.1:8088` | 기어, 와이퍼 변경 |
| 시연 경로 | 에뮬레이터 Extended Controls(⋯) → **Location → Routes → IMPORT GPX/KML** → [`demo/gpx/gilcap_forward.gpx`](demo/gpx/), [`gilcap_reverse.gpx`](demo/gpx/) | 위치, 진행 방향 |
| 마이크 | Extended Controls → **Microphone → Virtual microphone uses host audio input** 켜기 | 음성 입력 |
| 에뮬레이터 오디오 | AVD `config.ini`에 `hw.audioInput=yes`, `hw.audioOutput=yes` | 음성 입력·출력 |

- 에뮬레이터를 다시 켜면 `adb forward`와 마이크 설정을 다시 해 주세요.


### 시연 패널

에뮬레이터 한 대로 캡슐을 남기는 사람(A)과 여는 사람(B)을 함께 보여 주기 위해 시연 패널을 두었습니다. 화면의 **DEBUG** 버튼으로 열며, 정차(P단) 중에만 표시되고 주행(D단)으로 바꾸면 자동으로 닫힙니다. 패널에서는 사용자 A·B 전환, 시간대 덮어쓰기(실제·낮·밤·새벽), 현재 차량 상태와 판정 조건 확인, 전체 초기화를 할 수 있습니다.
 
---

## 시연 순서

### 바로 확인: 미리 심어둔 캡슐 열기 (약 1분)
앱에는 심사용 캡슐 1개(작성자 B, **맑음**, 정방향)가 들어 있습니다.
1. Virtual Console: **Gear → D**, **Wiper → Off**
2. Routes에서 `gilcap_forward` 재생
3. 안목 → 송정 구간 중간에서 "누군가 남긴 캡슐이 있어요" → 음성 재생 → 도감 수집
4. Routes 정지 → **Gear → P** → 도감 확인

같은 방법으로 `gilcap_reverse`를 재생하거나 와이퍼를 켜고 지나가면 **열리지 않습니다.**

### 전체 흐름: 남기기 → 조건 불일치 → 열기
| 장면 | 조작 | 기대 결과 |
|---|---|---|
| 1. A가 남기기 | P단에서 DEBUG → 사용자 **A** → Gear **D**, Wiper **Low** → `gilcap_forward` 재생 → 구간 중간에서 일시정지 → **[캡슐 남기기]** → 말하기 → **"등록"** | "비 오는 ○의 해안도로에 캡슐을 남겼어요" |
| 2. 반대 방향 | P단에서 사용자 **B** → Gear D, Wiper Low → `gilcap_reverse` 재생 | 열리지 않음 (방향 불일치) |
| 3. 맑은 날 | Wiper **Off** → `gilcap_forward` 처음부터 재생 | 열리지 않음 (날씨 불일치) |
| 4. 같은 조건 | Wiper **Low** → `gilcap_forward` 처음부터 재생 | **열림** → A의 메시지 재생 → 도감 수집 |
| 5. 도감 | Gear **P** → 도감 | "비 오는 ○의 해안도로" 캡슐 표시. D단에서는 숨김 |

시간대는 실제 시각 기준입니다. 장면 1과 4의 시간대가 달라지면 DEBUG 패널에서 같은 시간대로 맞춰 주세요.

## 안전 설계
- 주행 중 터치는 **[캡슐 남기기] 버튼 1번**만. 나머지는 음성으로 진행
- 캡슐은 한 번에 하나만 재생. 캡슐을 남기는 동안에는 발견을 멈춤
- 이미 수집한 캡슐과 자기 캡슐은 다시 열리지 않음
- 도감과 시연 패널은 **P단에서만** 표시
- 위치 등 민감한 로그는 debug 빌드에서만 기록

## 프로젝트 구조

SDK 연결부(core), 판정 규칙(domain), 저장소(data), 기능 흐름(feature)을 나누어 구성했습니다.

```
app/src/main/java/com/gilcap/app/
├─ core/       model, vehicle(Vehicle SDK), location(FusedLocation SDK), audio(STT·TTS SDK)
├─ domain/     matching(4조건 판정), repository
├─ data/       local(메모리 저장소)
├─ feature/    capsulecreate(음성 생성), capsulediscovery(발견·재생), collection(도감)
├─ ui/         주행 화면, 공통 컴포넌트
├─ debug/      시연 패널
└─ di/         조립
demo/gpx/      시연 경로 GPX
```
설계, 데이터 모델, 인터페이스, 기능 우선순위(P0/P1/P2)는 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)에 있습니다.

## 향후 계획 (P1)
- 희귀도: 조건이 드문 정도로 일반 / 레어 / 에픽 / 레전드 (예: 폭우 내리는 새벽)
- 흔적 발견: 위치·방향은 맞고 조건 하나가 다르면 "비 오는 밤에만 열리는 캡슐이 있어요" 힌트, 도감에 실루엣
- 차량 환경 재현: 캡슐을 남긴 순간의 공조 온도를 승인 후 적용
- 실제 목소리 캡슐, 서버 동기화
